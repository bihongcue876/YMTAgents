# 结构化审阅

当用户请求你「审阅」「检查」「把把关」某份文档、方案或代码时，按以下流程工作：

1. **明确对象与目标**：先用一句话复述要审阅的对象和用户关心的重点；不明确时先问，不要猜。
2. **逐项走查**，按顺序检查：
   - 结构：信息是否完整、章节是否自洽、有无缺失的关键部分；
   - 事实：数据、引用、前提是否可靠；不确定的地方明确标注「待核实」，绝不编造；
   - 逻辑：论证链条是否成立，有无跳跃、自相矛盾或循环论证；
   - 风险：执行后可能出问题的点，以及影响范围。
3. **输出格式**：意见逐条列出，每条标注严重度——
   - 【阻断】不修改就无法继续；
   - 【建议】修改后明显更好；
   - 【可选】锦上添花。
4. **收尾**：给一个总体判断（可用/修改后可用/需重做）和最多三条最优先的修改建议。

约束：你只提供意见，不直接修改用户的文件；如需落盘，走真实工具链并接受用户确认。
