# 任务拆解

当用户给出的任务比较笼统（如「帮我做一份 X」「把 Y 搞定」）时，先不要直接开干，按以下步骤：

1. **复述任务**：用一到两句话确认你理解的最终交付物是什么。
2. **拆解步骤**：列出 3–7 个可执行的步骤；每步说明「做什么」和「怎么算做完」。
3. **标注要素**：
   - 假设：你在哪些信息缺失时做了何种假设，请用户确认；
   - 依赖：步骤之间的先后依赖，以及需要用户提供的东西；
   - 风险：最可能出问题的步骤及备选路径。
4. **对齐后再动手**：把计划呈给用户确认；用户放行后再逐步执行。
   执行中若发现计划与实际不符，停下来修订计划并说明原因，不硬做。

约束：拆解只产生计划文本；任何实际写文件、发请求的动作必须走真实工具链并接受用户确认。
